# PiVo acoustic parity

Source: `PiVo-1.4M` revision `515d84fc3420da6ae138f1b81017fcbc24d622a8`; reconstruction `src_id/acoustic.py` based on the architecture and multilingual reference `pivo-v1-multilingual` revision `5abd1516c5ea8be8fd5a6ac9673d8762fbe74eb6`. Checkpoint loaded with `weights_only=True` and `strict=True`, 584,965 trainable parameters.

The original CPU test on 2026-11-08, using workspace `.venv`, PyTorch 2.11.0+cu128 and ONNX Runtime 1.31.1, found a maximum absolute difference of `9.16e-05` on two English sequences (34/53 tokens), both voice IDs, against an absolute-only threshold of `2e-04`. That limited result is **not a pass** at the planned mixed tolerance.

The expanded test now checks each element using `rtol=1e-4, atol=1e-5`, including decoder cache outputs at every 16-frame chunk. The CPU run **fails** with 69 failed comparisons: 67 `key0` cache comparisons and two feature comparisons (full and streaming, both on the 53-token sequence, voice 0). Length-1 input and independently seeded nonzero cache inputs pass. The synthetic 511-token sequence exercises near the reference server's default 512-token cap; its decoder uses one frame per phone (398 frames) to bound full-decoder memory. Encoder and duration comparisons pass on these tested inputs. A failed cache value can remain in the rolling cache and be counted again in later comparisons, so 69 is not a count of independent errors.

Both runtimes used one CPU thread. Repeating with ONNX graph optimizations and PyTorch MKLDNN disabled produced the same 69 failed comparison labels; no tolerance was relaxed. The first mismatch is `key0` for the 34-token sequence, voice 0, at chunk position 80: `0.0124922544` versus `0.0124776363` (absolute difference `1.46e-05`); this same stored value appears in subsequent cache comparisons. The only failed feature element, at frame 390, feature 1 of the 53-token sequence, voice 0, differs by `2.78e-05` (full) and `2.83e-05` (stream). Absolute discrepancies are small on the observed feature scale, but their perceptual or training significance has not been evaluated. Later-position `key0` differences and recurrence through the rolling cache are consistent with positional numerical discrepancies; the precise source is not established. A standalone ONNX/PyTorch sine comparison at integer positions up to 511 differed by at most `5.96e-08`, insufficient to establish a cause. ONNX export after training is still outstanding.

See `tests/test_parity.py` for exact tokens and checks; no training has been performed.
